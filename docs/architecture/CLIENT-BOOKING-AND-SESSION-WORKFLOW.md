# Client Portal Phase 3 — Self-Service Booking & Project Inquiry Architecture

## 1. Overview

Phase 3 converts `/portal/book` (`ClientBookSessionPage.jsx`) from a Phase 2 placeholder into a two-branch, three-step self-service booking and post-production inquiry flow on the existing Spatial Ambient Workspace foundation, operating strictly under Firebase Spark Plan constraints (no Cloud Functions, no Workers, no external paid APIs).

## 2. Sanitized Public Pricing Catalog (`publicPricingCatalog/current`)

- **Source of Truth**: `settings/pricing` (Owner-only writable, contains internal `fees`, `operationalSettings`, `updatedByUid`, and draft/`unconfigured` options).
- **Public Projection (`src/features/public-pricing/`)**:
  - Generated by `buildPublicPricingProjection()` and written atomically to `publicPricingCatalog/current` inside the same Firestore transaction (`savePricingSettingsTransaction`) whenever Owner saves Price & Fee Settings.
  - Strictly strips all internal `fees`, `operationalSettings`, and `updatedByUid`, and omits inactive services, inactive options, and `unconfigured` options.
  - Supports a one-click manual Owner backfill (`syncPublicPricingCatalog` + `PublicPricingSyncBanner` in `PriceAndFeeSettingsPage.jsx`) when an existing workspace already has persisted `settings/pricing` V2 settings but no published `publicPricingCatalog/current` yet. Zero auto-writes occur on read/load.
  - **Fail Closed**: `usePublicPricingCatalog` and `normalizePublicPricingCatalog` never fall back to `DEFAULT_PRICING_SETTINGS` when `publicPricingCatalog/current` is missing, malformed, or contains forbidden internal fields.

## 3. Reconciled Customer & Canonical Pricing Math

All customer-facing and Admin pricing calculations share `computeCustomerPricingCore()` in `src/features/admin/calendar/utils/booking-pricing.js`:

- **Hourly (`hourly`)**: Rounds partial studio hours **up** per billed hour (`Math.ceil(durationMinutes / 60) * hourlyRate`). Applies single best active `discountRules` option (capped at `subtotal`, never stacking).
- **Fixed Shift (`fixed_shift`)**: Covers package `basePrice - discountAmount` for `baseDurationMinutes`. When extended past `baseDurationMinutes`, extension hours are billed **only** using the active `hourly` option rate within the **same** `serviceType` (`findServiceExtensionHourlyRate(serviceType)`), rounded up per extra hour (`Math.ceil((duration - baseDuration) / 60)`), keeping the package's own `discountAmount` without stacking hourly discount rules. If no active `hourly` option exists in that `serviceType`, extension is disabled.
- **Fixed Project (`fixed_project`) & Manual Quote (`manual_quote`)**: Fixed project price displays its configured total; Manual Quote returns `isManualQuote: true, estimatedTotal: null` (`"Custom Quote"`, never `Rp 0`).
- **Customer Boundary**: `calculateCustomerPriceEstimate()` requires `publicPricingCatalog/current` and returns zero internal fee or commission fields.

## 4. Two-Branch 3-Step Flow (`/portal/book`)

1. **Studio Booking (`deliveryMode === 'studio'`)**
   - **Step 1 — Select Session**: Active Studio categories & configured packages/options from `publicPricingCatalog/current`.
   - **Step 2 — Choose Schedule**: Duration selector (respecting Fixed Shift base/extension constraints), Room preference (`No Preference` / `Room A` / `Room B`), Asia/Jakarta date picker, and hourly time-slot matrix (`10:00 – 22:00 WIB`) sourced strictly from `usePublicAvailability()` (`publicAvailability` + `publicAvailabilityMetadata/status`, fail closed when unready).
   - **Step 3 — Review & Send**: Prefilled Client profile contact (`useAuth()`), tentative price estimate & disclaimer, required privacy consent, honeypot + single-flight lock -> `submitClientBookingRequest()`.
2. **Project Inquiry (`deliveryMode === 'wfa'`, e.g., Mix & Master)**
   - **Step 1 — Select Service**: Active WFA category & tier.
   - **Step 2 — Project Details**: Project/Artist Name, optional Project Type (`Single`, `EP`, `Album`, `Other`), optional Track Count, optional Target Deadline, and Project Brief — with **zero** studio room, duration, or calendar slot UI.
   - **Step 3 — Review & Send**: Customer-safe price or `Custom Quote`, prefilled contact, consent -> `submitClientBookingRequest()`.

## 5. Booking Request Ownership & Admin Conversion

- Client Portal requests write to `publicBookingRequests/{requestId}` (`38` exact keys, extending the `33`-key anonymous schema with `clientUid`, `customerId`, `serviceOptionId`, `serviceOptionName`, and `pricingVersion`, and setting `source: 'client_portal'`).
- Anonymous public requests (`public_landing_page`, `public_availability_calendar`) remain untouched (`33` keys).
- Firestore Rules enforce:
  - Only `isActiveClient()` can create `client_portal` requests with matching `clientUid == request.auth.uid`, bound `customerId`, `status == 'new'`, `linkedBookingId == null`, and `pricingVersion == publicPricingCatalog/current.version`.
  - Clients can read/list only their own `client_portal` requests and cannot update or delete them; suspended clients are blocked.
  - Staff see a `Client Portal` badge, `serviceOptionName`, and `pricingVersion` in `AdminBookingRequestsPage` + `BookingRequestDetailDrawer`, and `/admin/calendar` (`mapPublicServiceToInternalPricing`) prefills the exact active `serviceOptionId` & duration (or forces manual selection if that package was since deactivated) for atomic booking confirmation.
