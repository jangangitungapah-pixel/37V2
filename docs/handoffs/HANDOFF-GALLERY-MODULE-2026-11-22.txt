1. IMPLEMENTATION SUMMARY
-------------------------
Implemented the Gallery Management module (/admin/gallery) and dynamic public
Landing Page Gallery integration for 37 Music Studio:

- Top-Level Admin Navigation & Routing:
  * Added "Gallery" at order 08 (/admin/gallery) and shifted "Settings" to order 09
    in src/features/admin/navigation/admin-navigation.js.
  * Mounted /admin/gallery inside RequireStaff & AdminLayout in src/App.jsx.
  * Updated docs/architecture/ADMIN-SHELL-NAVIGATION.md and existing navigation
    regression suites (admin-shell.test.jsx, settings.test.jsx, settings-center.test.jsx)
    for the 9-item navigation menu.

- Cloudinary Direct Unsigned Upload & Delivery Optimization:
  * Configured public environment template (.env.example) with:
    VITE_CLOUDINARY_CLOUD_NAME=fodgcil9
    VITE_CLOUDINARY_UPLOAD_PRESET=37gallery
  * Zero API Secret, API Key, or signed upload logic is present in client code,
    environment files, logs, or docs.
  * Direct unsigned POST to https://api.cloudinary.com/v1_1/fodgcil9/image/upload
    using native FormData (file, upload_preset) with concurrency capped at 2 files.
  * Client-side usability validation (JPG/JPEG/PNG/WEBP/AVIF only; rejects SVG, GIF,
    video, PDF, executables; max 10 MB; max 6000 x 6000 px; rejects 0-byte files).
  * Strict Cloudinary response validation (public_id, asset_id, HTTPS res.cloudinary.com
    secure_url matching cloudName, resource_type == "image", format, positive integer
    width, height, bytes).
  * Partial failure recovery: if Cloudinary upload succeeds but Firestore metadata creation
    fails, the validated Cloudinary response and pre-generated galleryItemId are preserved
    in the queue state, displaying the cloudinaryPublicId and exposing "Retry Save Metadata"
    without re-uploading the file.
  * Responsive delivery transformations (f_auto,q_auto,c_limit,w_<width>) for Admin
    thumbnails (w_600), Landing Page cards (w_900), and Lightbox view (w_1600).

- Firestore Metadata Model, Publication, Ordering & Security Rules:
  * Collection: galleryItems/{galleryItemId} (strict 22-key schema, schemaVersion: 1,
    optimistic concurrency version starting at 1 and incrementing by +1 on every update).
  * Status lifecycle: draft -> published -> draft (unpublish), or archived -> draft (restore).
    Archived items cannot transition directly to published, and publishing requires valid
    non-empty altText (>= 3 characters). Permanent Firestore deletion is disabled.
  * Atomic two-document transaction swap (swapGallerySortOrderTransaction) for Move Up /
    Move Down ordering of published items by sortOrder ASC.
  * Added match /galleryItems/{galleryItemId} to firestore.rules and composite index
    (status ASC, sortOrder ASC) to firestore.indexes.json (referenced in firebase.json).

- Public Landing Page Dynamic Integration:
  * Created usePublishedGallery() subscribing to where('status', '==', 'published'),
    orderBy('sortOrder', 'asc'), limit(100) via Firestore onSnapshot.
  * Removed the 4 static demo SVG items (gallery-guitar.svg, gallery-drums.svg,
    gallery-mic.svg, gallery-console.svg) from landingPageContent.gallery.items.
  * Preserved the Landing Page Neo-Brutalist Editorial design and GalleryLightboxDialog
    while supporting Loading skeleton, Empty state ("Studio photos coming soon." with
    "View all photos" hidden), Error fallback state, and Published responsive photo grid.
