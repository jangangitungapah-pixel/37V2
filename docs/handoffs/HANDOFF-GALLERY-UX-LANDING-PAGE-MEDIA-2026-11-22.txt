1. SUMMARY OF UX CHANGES (/admin/gallery)
-----------------------------------------
Redesigned /admin/gallery into a natural, mobile-first photo-library
experience similar to a smartphone Gallery app:

- Two Workspace Tabs:
  1) Photos (default active tab):
     - Responsive square photo grid (3 columns on mobile phones, 4 on tablet,
       5 on desktop) occupying the main screen.
     - Header "+ Add Photos" button opens the device multi-file picker directly.
     - Simple filter pills: Semua, Galeri Website, Tersembunyi, Arsip + title search.
     - Photo tiles show only the photograph, a subtle title overlay, and tiny
       publication/usage badges ("Galeri #N", "Used on Landing Page", "Arsip").
     - Technical metadata (Cloudinary publicId/assetId, Firestore IDs, dimensions,
       bytes, format, schemaVersion, record version, UIDs, raw timestamps) is
       preserved in Firestore but removed from the everyday photo grid.
     - Tapping a photo opens a mobile bottom-sheet / desktop modal detail view
       (GalleryItemPreviewDialog) with natural labels ("Judul Foto", "Deskripsi",
       "Tampilkan di Galeri Website", "Sembunyikan dari Galeri", "Edit Foto",
       "Arsipkan Foto", "Pulihkan Foto", "Geser Naik", "Geser Turun").
     - Completed upload queue rows automatically collapse out of view, while
       in-progress uploads and failed uploads (including "Simpan Ulang Foto" /
       Retry Save Metadata without re-uploading the binary) remain recoverable.
  2) Landing Page:
     - Dedicated Landing Page Media Manager for the 4 fixed website image
       placements and their copywriting.

2. SUMMARY OF LANDING PAGE MEDIA MANAGEMENT
-------------------------------------------
- Four Fixed Placements in collection landingPagePlacements/{placementId}:
  1) hero-featured -> landingPageContent.hero.featuredPhoto
     Editable copy: topSticker, captionTitle, captionSubtitle,
     floatingBadgeTitle, floatingBadgeSubtitle + altText.
     Automatically removes/hides DEMO PREVIEW and DEMO ASSET when a real
     photo is configured.
  2) room-a -> landingPageContent.rooms.items (id === "room-a")
     Editable copy: sticker, name, capacityLabel, tags (1..6), ctaLabel + altText.
     Preserves immutable room.id ("room-a") and defaultService ("rehearsal").
  3) room-b -> landingPageContent.rooms.items (id === "room-b")
     Editable copy: sticker, name, capacityLabel, tags (1..6), ctaLabel + altText.
     Preserves immutable room.id ("room-b") and defaultService ("recording").
  4) studio-exterior -> landingPageContent.testimonialsAndContact.contact.image
     Editable copy: optional caption rendered unobtrusively below the location
     image + altText.

- Photo Selection & Upload Workflow:
  * Tapping "Ganti Foto" opens a thumbnail-only photo picker reusing the
    Gallery library, highlighting the currently selected photo.
  * Supports assigning the same Gallery photo to multiple placements and
    uploading a brand-new photo directly inside the picker ("Upload New Photo").
  * Gallery library publication status (galleryItems.status) and Landing Page
    placement publication status (landingPagePlacements.status) are independent.
  * All 4 old dummy SVG sources (/images/demo/room-a-live.svg,
    /images/demo/room-b-control.svg, /images/demo/location-exterior.svg) have
    been removed from active rendering and fall back to a neutral StudioImage
    placeholder when unconfigured.
  * Public GalleryLightboxDialog now displays the photo's caption alongside
    its accessibility description.

3. FIRESTORE DATA MODEL & SECURITY RULES CHANGES
------------------------------------------------
- Preserved galleryItems/{galleryItemId} strict 22-field schema and rules.
- Added landingPagePlacements/{placementId} strict 19-field schema and rules
  in firestore.rules:
  * Fixed placementId allow-list: hero-featured, room-a, room-b, studio-exterior.
  * Placement-specific copy map validators: isValidHeroFeaturedCopy,
    isValidRoomPlacementCopy, isValidStudioExteriorCopy.
  * Active Owner can read all placements and create (version == 1) or update
    (version == resource.data.version + 1) valid placements.
  * Anonymous visitors and Active Staff can read only when status == "published".
  * Inactive accounts are denied all reads and writes.
  * Delete is prohibited (allow delete: if false).
- Public query uses where("status", "==", "published"), limit(10).
