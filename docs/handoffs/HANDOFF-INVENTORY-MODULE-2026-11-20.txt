4. ITEM TYPES & CORE OPERATIONAL WORKFLOW
============================================================

- Supports a fast 4-step daily workflow (`Search -> Select -> Record Movement -> Done`):
  1. Consumables (`itemType: 'consumable'`):
     - Tracks supplies (guitar strings, drum sticks, picks, batteries, gaffer tape, cleaning liquid, cable ties) via `consumableStock.onHandQuantity` (decimal precision up to 3 decimal places via `roundInventoryQuantity` / `hasAtMostThreeDecimals`).
     - Automatic status derivation (`deriveConsumableStockStatus`) against `minimumStockQuantity`: `out_of_stock` (`0`), `low_stock` (`> 0 && <= minimumStockQuantity`), `in_stock` (`> minimumStockQuantity`).
  2. Equipment (`itemType: 'equipment'`):
     - Tracks reusable gear at a single primary studio location via four non-negative integer condition buckets: `availableQuantity`, `maintenanceQuantity`, `damagedQuantity`, `retiredQuantity` (`registeredTotal = sum of all four`).
     - Threshold field `minimumAvailableQuantity` triggers low-available alerts while preserving retired/maintenance/damaged history.
- Summary metrics (`computeInventorySummaryMetrics`) deduplicate records across states (e.g., an item in maintenance with an overdue schedule is counted once).

6. MOVEMENT TYPES, TRANSITIONS & MAINTENANCE SCHEDULING
============================================================

- Consumable movements: `opening_stock` (when `openingQuantity > 0`), `stock_in`, `consume` (Record Usage with preset reasons: `Studio Operations`, `Customer Session`, `Maintenance`, `Other`), `write_off`, `stock_adjustment` (Owner-only).
- Equipment movements: `opening_stock` (when initial `availableQuantity > 0`), `stock_in` (Add Equipment), `send_to_maintenance`, `return_from_maintenance` (records `lastMaintenanceDate` and optional `nextMaintenanceDate`), `mark_damaged` (`available` or `maintenance` source bucket), `mark_repaired` (requires Repair Note >= 3 chars), `mark_retired` (`available` or `damaged` source bucket), `stock_adjustment` (Owner-only bucket reconciliation), `location_changed`.
- Maintenance reminders anchored in `Asia/Jakarta` via `getJakartaTodayIso()` (`deriveEquipmentMaintenanceMeta`):
  - `due` (Maintenance Due): `nextMaintenanceDate <= todayIso`
  - `soon` (Maintenance Soon): `todayIso < nextMaintenanceDate <= todayIso + 7d`
  - `scheduled`: `nextMaintenanceDate > todayIso + 7d`
  - `none`: No next date configured (visual reminder only; never mutates stock automatically).

7. TRANSACTION ATOMICITY, IDEMPOTENCY & OPTIMISTIC LOCKING
============================================================

- Entry points (`services/inventory-item-service.js` and `services/inventory-movement-service.js`):
  - `createInventoryItem()`
  - `updateInventoryItemMetadata()`
  - `setInventoryItemArchiveStatus()`
  - `recordInventoryMovement()`
- All mutations execute in Firestore `runTransaction` with all reads before writes:
  1. Pre-generated stable `movementId` (`operationId`) from UI dialogs guarantees idempotent replay on transient retry without double-counting stock.
  2. Optimistic `expectedVersion === existingItem.version` check (`inventory/stale-version`) prevents overselling under concurrent Staff edits.
  3. Direct editing of stock quantities in item metadata dialogs is strictly disallowed.

8. SOFT ARCHIVE RULES & ROLE RESTRICTIONS
============================================================

- Permanent deletion is blocked (`allow delete: if false` in Firestore Rules; no delete UI).
- Archiving (`isActive = false`) via `checkArchiveEligibility` / `setInventoryItemArchiveStatus` is allowed only when operational stock is zero:
  - Consumables: `onHandQuantity === 0`
  - Equipment: `availableQuantity === 0 && maintenanceQuantity === 0 && damagedQuantity === 0` (`retiredQuantity >= 0` allowed).
- Active Staff & Owner (`isActiveStaff()`): Can read inventory, create items, edit metadata, record routine movements, and soft-archive eligible 0-stock items.
- Active Owner Only (`isActiveOwner()`): Exclusively authorized to execute `stock_adjustment` movements and reactivate archived items (`isActive: false -> true`). Staff UI hides Stock Adjustment and Reactivate controls cleanly.

9. FIRESTORE COLLECTIONS & ZERO-COMPOSITE-INDEX QUERY STRATEGY
============================================================

1. `inventoryItems/{itemId}` (32 validated schema fields)
   - Maintains atomic query booleans `lowStock`, `inMaintenance`, `hasDamagedOrRetired` inside item creation and movement transactions.
2. `inventoryMovements/{movementId}` (19 validated immutable fields)
   - Stores deltas, before/after snapshots (`quantityBefore`/`quantityAfter` or bucket maps), `locationBefore`/`locationAfter`, `actorUid`/`actorName`/`actorRole`, `reason`, `notes`, and `occurredAt`.
- Single-field queries only (zero custom `firestore.indexes.json` required):
  - Directory (`orderBy('updatedAt', 'desc'), limit(maxLimit + 1)` with `PAGE_SIZE = 50`) and Archived (`where('isActive', '==', false), limit(maxLimit + 1)`).
  - Server-side `getCountFromServer()` aggregations + bounded `INVENTORY_ITEMS_SUMMARY_BOUND = 500` deduplication for Active Items, Low Stock, Maintenance, and Damaged / Retired KPI cards.
  - Item history (`where('itemId', '==', itemId)`) with `PAGE_SIZE = 20` and Global Activity (`orderBy('occurredAt', 'desc')`) with `PAGE_SIZE = 30`.
