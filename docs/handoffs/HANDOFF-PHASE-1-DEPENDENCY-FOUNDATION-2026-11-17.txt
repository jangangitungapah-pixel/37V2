============================================================
6. KEY ARCHITECTURE / USAGE BOUNDARIES
============================================================

- Keep JavaScript/JSX. No TypeScript migration has been requested.
- Build UI with Tailwind v4 + Base UI primitives + shadcn local source
  components. Add only the components needed for a user-approved page;
  do not install the full component catalogue pre-emptively.
- Use Motion selectively. Respect prefers-reduced-motion and avoid
  expensive always-on animation.
- Prefer component-local React state. Use Zustand only for state that is
  genuinely shared across views.
- Use TanStack Query for conventional async request state. Do not mirror
  Firestore real-time subscriptions into a duplicate cache without a
  specific reason.
- Use modular Firebase SDK functions and Firestore listeners only when
  a user-approved phase defines the flow.
- Load ECharts and other heavy feature modules lazily, where required.
- Store timestamps canonically and handle the studio/business timezone
  explicitly; do not assume the browser's timezone is authoritative.
- Only Firebase Web SDK is present. There is no provisioned Firebase
  project, auth flow, Firestore schema, security rules, hosting config,
  or deployment from this phase.
- No .env.local or credentials should ever be committed.
