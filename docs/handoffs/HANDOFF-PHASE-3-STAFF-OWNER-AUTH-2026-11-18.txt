3. AUTHENTICATION ARCHITECTURE
============================================================

- `src/lib/firebase/client.js`: Single default Firebase App lazy initializer
  (`getFirebaseApp()`) and configuration validator (`isFirebaseConfigured()`).
- `src/lib/firebase/auth.js`: Shared lazy Firebase Auth instance (`getFirebaseAuth()`).
- `src/lib/firebase/firestore.js`: Shared lazy Cloud Firestore instance (`getFirebaseDb()`).
- `src/features/auth/auth-helpers.js`: Allowed role validation (`owner`, `staff`)
  and centralized error mapping (`mapAuthErrorToMessage`, `mapPasswordResetErrorToMessage`).
- `src/features/auth/staff-profile-service.js`: Reads and validates
  `staffProfiles/{authenticatedUser.uid}` (document exists, ID matches UID,
  `active === true`, `role` is `owner` or `staff`).
- `src/features/auth/auth-service.js`: Modular Email/Password sign-in
  (`signInWithEmailAndPassword`), profile verification with immediate `signOut`
  on unauthorized profiles, password reset (`sendPasswordResetEmail`), and
  session listener (`onAuthStateChanged`).
- `src/features/auth/AuthProvider.jsx` & `AuthContext.js`: Central React context
  managing session restoration, race-safe profile verification, and `login`,
  `logout`, and `resetPassword` actions.
- `src/features/auth/RequireStaff.jsx`: Route guard protecting `/admin` with a
  branded loading screen while authentication is being verified.

4. FIRESTORE DATA MODEL (`staffProfiles`)
============================================================

Collection: `staffProfiles`
Document ID: `{FIREBASE_AUTH_UID}`

Required fields:
- `displayName` (string): Staff or owner display name
- `email` (string): Account email reference
- `role` (string): `"owner"` or `"staff"`
- `active` (boolean): `true` for active access, `false` to revoke access
- `createdAt` (timestamp): Firestore Timestamp of profile creation

No public registration or client-side profile creation/editing exists.

============================================================
5. FIRESTORE SECURITY RULES (`firestore.rules`)
============================================================

```javascript
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    match /staffProfiles/{uid} {
      allow get: if request.auth != null
                 && request.auth.uid == uid;
    }

  }
}
```

- Authenticated users can only `get` their own `staffProfiles/{uid}` document.
- Unauthenticated reads, reading other users' profiles, listing `staffProfiles`,
  client-side profile writes (`create`, `update`, `delete`), and access to any
  other collection are denied.

============================================================

- Header `Client Login` button (desktop & mobile drawer) opens the
  `Client Login Coming Soon` dialog (`"The client portal is not available yet..."`)
  and never routes to `/staff/login` or `/admin`.
- Footer `Staff / Owner Login` button uses React Router `<Link to="/staff/login">`
  to navigate to the real Firebase-backed Staff & Owner Login page.
- `/staff/login` provides:
  - Neo-Brutalist Editorial split layout (mobile-first single column expanding
    to a desktop 5/7 split with `"BEHIND THE SOUND."` identity panel).
  - Email and Password inputs with show/hide password toggle, email trimming,
    loading state, and accessible error alerts.
  - Functional Forgot Password flow calling `sendPasswordResetEmail` with
    generic confirmation copy (`"If an account matches this email address,
    password reset instructions will be sent."`).
  - Automatic redirect to `/admin` when an active Owner or Staff session is
    already authenticated.
- `/admin` (Protected Temporary Admin Portal):
  - Guarded by `<RequireStaff>`. Unauthenticated visitors are redirected to
    `/staff/login`.
  - Displays real authenticated `displayName`, `email`, and `ROLE: OWNER` or
    `ROLE: STAFF` badge from Firebase Auth + `staffProfiles/{uid}`.
  - Includes functional `Sign Out` button and `Return to public website` link.
  - Contains no fake revenue, booking counts, customer counts, occupancy figures,
    or chart widgets.
