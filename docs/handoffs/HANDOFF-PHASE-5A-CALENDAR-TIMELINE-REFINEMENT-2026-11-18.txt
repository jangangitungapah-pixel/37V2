3. UNIFIED DAY / WEEK / MONTH TIMELINE BEHAVIOR
============================================================

All three calendar views (`Day`, `Week`, `Month`) now render through a single
shared hourly timeline engine (`CalendarTimelineGrid.jsx`) backed by one CSS Grid
containing both column headers and body rows so headers and timeline tracks can
never drift out of alignment:

- Day View (`CalendarDayView.jsx`):
  Displays a single date with `Room A` and `Room B` side-by-side (or only the
  selected room when filtered) inside the `10:00 – 22:00 WIB` hourly timeline.
- Week View (`CalendarWeekView.jsx`):
  Displays 7 consecutive Monday-to-Sunday columns with sticky left `WIB` clock
  column (`left-0`), simultaneous Room A & Room B visibility separated into
  collision lanes by `computeTimelineOverlapLayout`, and clickable date headers
  to open `Day View`.
- Month View (`CalendarMonthView.jsx` — Rebuilt):
  Replaced traditional date-box cells with a unified full-month horizontal
  timeline showing every actual calendar day of the active month (`28`, `29`,
  `30`, or `31` columns — zero filler dates from neighboring months and zero
  `+N booking` truncation). Clicking any day header jumps to `Day View`;
  horizontal scrolling glides across the entire month while keeping `WIB` sticky
  on the left.

4. DISPLAY TIME INTERVAL REFINEMENT (1-HOUR, 10:00–22:00)
============================================================

- Separated UI display interval config in `calendar-config.js`:
  - `CALENDAR_DISPLAY_INTERVAL_MINUTES = 60`
  - `CALENDAR_DISPLAY_START_MINUTE = 600` (`10:00 WIB`)
  - `CALENDAR_DISPLAY_END_MINUTE = 1320` (`22:00 WIB` visual end boundary)
  - `CALENDAR_TIMELINE_ROW_HEIGHT_PX = 60` (`1px = 1 minute` linear scale)
  - `TIMELINE_HOURLY_SLOTS`: `10:00` through `21:00` (12 hourly slots).
- `22:00` renders exclusively as the read-only bottom timeline boundary label
  and is NOT a clickable slot start row. Zero `10:30` / `11:30` timeline rows
  exist.
- Proportional booking coordinates (`computeHourlyTimelineBlockMetrics`):
  - Existing `HH:30` start times and custom 30-minute bookings render at their
    exact fractional offset and proportional height (e.g., `10:30–11:00` = `30px`
    half-row; never rounded up to 1 full hour).
  - Editing an existing `HH:30` or post-`22:00` booking preserves its original
    start time in `BookingFormDialog` as a `(Jadwal Eksisting)` option.
  - Any session extending past or starting at/after `22:00 WIB` triggers explicit
    interactive overflow badges (`Sesi lewat 22:00 WIB`) so no late booking is
    hidden.
