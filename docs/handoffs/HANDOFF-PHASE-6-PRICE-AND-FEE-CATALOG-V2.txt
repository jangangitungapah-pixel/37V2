4. SERVICE CATALOG STRUCTURE
============================================================

Hierarchical catalog:
  Service Type (deliveryMode: 'studio' | 'wfa')
    -> Service Option / Subcategory
         -> Customer Price + Discount Rules + Internal Fees (Staff / Owner / Recording Operator)
  Global Operational Settings
    -> Daily Meal Allowance per Staff

Default V2 Catalog (`DEFAULT_SERVICE_TYPES`):
- Studio Services (`deliveryMode: 'studio'`):
  1. Rehearsal (`rehearsal`):
     - Reguler (`rehearsal-regular`): hourly Rp 100.000/jam + Diskon Durasi Rp 30.000 / 3 jam
     - Paket 3 Hours (`pkg-rehearsal-3h`): fixed_shift 180m, Rp 300.000 - Rp 30.000 = Rp 270.000
     - Paket 5 Hours (`pkg-rehearsal-5h`): fixed_shift 300m, Rp 500.000 - Rp 50.000 = Rp 450.000
     - Paket 6 Hours (`rehearsal-pkg-6h`): unconfigured, isActive=false (no invented rate)
  2. Recording (`recording`):
     - Lite (`rec-lite`): unconfigured, isActive=false
     - Pro (`rec-pro`): unconfigured, isActive=false
     - Live (`live-recording-3h`): fixed_shift 180m, Rp 420.000
     - Drum Only (`rec-drum-only`): unconfigured, isActive=false
     - Others (`rec-others`): manual_quote, staff=manual, recordingOperator=manual
     - Tracking Reguler (`tracking-regular`): hourly Rp 150.000/jam
     - Multitrack Shift (`multitrack-shift-6h`): fixed_shift 360m, Rp 800.000
- WFA Services (`deliveryMode: 'wfa'`, excluded from Studio Room Calendar):
  3. Mixing (`mixing`): Mixing Reguler (`mixing-regular`, hourly Rp 250.000/jam)
  4. Mastering (`mastering`): Mastering Reguler (`mastering-regular`, hourly Rp 300.000/jam)

Supports Owner Add/Edit/Toggle/Safe-Delete for both Service Types and Subcategories
with immutable UUIDs on rename. Active Staff view `/admin/settings/price-and-fee` in
read-only mode.

============================================================
5. PRICING MODE
============================================================

Five explicit modes (`PRICING_MODES`), using integer Rupiah math:
- `hourly`: `Math.round((hourlyRate * durationMinutes) / 60)` + optional non-stacking
  `discountRules` (`per_completed_block` or `minimum_duration`, highest single rule wins,
  capped at subtotal).
- `fixed_shift`: fixed `durationMinutes`, `basePrice`, built-in `discountAmount`
  (`final = max(0, basePrice - discountAmount)`), never stacked with regular discount rules.
- `fixed_project`: fixed `projectPrice` + optional `unitLabel` (for WFA / project services).
- `manual_quote`: negotiated customer total entered at booking time (`> 0`).
- `unconfigured`: forced `isActive: false`, hidden from Booking Form, rejected by schema/service.

============================================================
6. FEE CALCULATION
============================================================

Three independent internal roles per subcategory (`fees.staff`, `fees.owner`,
`fees.recordingOperator`), each supporting `none | fixed | hourly | manual`:
- `none`: Rp 0
- `fixed`: flat integer `amount` per booking
- `hourly`: `Math.round((amount * durationMinutes) / 60)`
- `manual`: entered at booking time (default for Staff & Recording Operator on `Recording -> Others`)

Global `operationalSettings.dailyMealAllowancePerStaff`: operational preset only;
never included in booking totals or per-booking fee snapshots.
Internal fees are strictly isolated from Customer Bill (`subtotal`, `discountAmount`,
`totalAmount`, DP, remaining balance). Fixed and hourly cannot be active simultaneously
on the same role.

============================================================
7. FIRESTORE SCHEMA V2
============================================================

Single document `settings/pricing`:
- `schemaVersion`: `2`
- `serviceTypes`: Array of Service Type objects containing nested `options`
- `operationalSettings`: `{ dailyMealAllowancePerStaff: int >= 0 }`
- `version`: positive integer incremented transactionally (`expectedVersion`)
- `updatedAt`: Firestore `serverTimestamp()`
- `updatedByUid`: `request.auth.uid` (active Owner)

Shared realtime hook `usePricingSettings()` subscribes via `onSnapshot` with zero
`localStorage` source of truth and clean unsubscribe on unmount.

============================================================
8. MIGRATION RESULT
============================================================

Implemented pure, idempotent `migratePricingSettingsV1ToV2()` in
`src/features/admin/settings/pricing/utils/migrate-pricing-settings.js`:
- Detects legacy V1 documents (`schemaVersion === 1` or `sessionTypes` without `serviceTypes`).
- Migrates in memory during read without issuing any automatic Firestore write.
- Preserves all V1 hourly rates, Recording Options, Studio Packages, duration/regular
  discounts, rehearsal staff hourly commission, package staff/operator commissions,
  `dailyMealAllowancePerStaff`, `version`, `updatedAt`, and `updatedByUid`.
- Surfaces a clear migration banner in `PriceAndFeeSettingsPage` so the Owner explicitly
  reviews and persists Schema V2 at `version + 1`.
- Verified idempotence and lossless mapping in `settings.test.jsx` Section D.

9. RULES UPDATES (`firestore.rules`)
============================================================

- `match /settings/pricing`:
  - `allow get: if isActiveStaff();`
  - `allow list: if false;`
  - `allow create: if isActiveOwner() && isValidPricingSettings(request.resource.data) && request.resource.data.version == 1;`
  - `allow update: if isActiveOwner() && isValidPricingSettings(request.resource.data) && request.resource.data.version == resource.data.version + 1;`
  - `allow delete: if false;`
  - Enforces `schemaVersion == 2`, non-empty `serviceTypes` list, exact 6 top-level keys,
    valid `operationalSettings.dailyMealAllowancePerStaff >= 0`, `updatedAt is timestamp`,
    and `updatedByUid == request.auth.uid`.
- `match /bookings/{bookingId}`:
  - Accepts V2 service metadata fields (`serviceTypeId`, `serviceTypeName`, `serviceOptionId`,
    `serviceOptionName`, `deliveryMode`, `pricingMode`, `pricingSettingsVersion`) and enforces
    `deliveryMode == 'studio'` (blocking WFA bookings at the database layer).
  - Supports both V1 and V2 `commissionSnapshot` via ternary schema dispatch
    (`isValidBookingCommissionSnapshotV2` / `isValidBookingCommissionSnapshotV1`) plus null
    Phase 5 snapshots.
  - Enforces exact key sizes & `affectedKeys()` validation on updates so complex V2
    bookings stay comfortably within Firestore Rules' 1000-expression evaluation budget.
  - Protects customer price snapshot, `automaticDiscount`, `commissionSnapshot`, and
    payment snapshot from tampering when booking service scope is unchanged.
  - Preserves `allow delete: if false;`.

  blocked from creating room bookings or `bookingSlots` locks.

============================================================
11. HISTORICAL SNAPSHOT PROTECTION
============================================================

- Changing Settings V2 never mutates existing bookings.
- New bookings snapshot customer totals, `automaticDiscount`, V2 catalog IDs/names, and
  3-role `commissionSnapshot` V2 at creation time.
- Editing notes/contact info/status or rescheduling room/date/time preserves historical
  financial & commission snapshots identically.
- Changing service/subcategory/duration during edit requires explicit confirmation
  (`Terapkan harga & fee preset terbaru`) before recalculating snapshots.
- Legacy Phase 5 (`commissionSnapshot: null`) and Phase 6 V1 (`staffBasis`/`staffAmount`)
  bookings remain readable and updatable without forced database migration.
