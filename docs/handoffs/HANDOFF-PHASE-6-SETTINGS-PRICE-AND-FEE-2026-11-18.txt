4. SETTINGS FEATURES
============================================================

1. Section 01 — Session Types:
   - Existing V2 defaults: Rehearsal (Rp 100.000/jam), Recording (Rp 150.000/jam),
     Mixing (Rp 250.000/jam), Mastering (Rp 300.000/jam).
   - Supports Add/Edit modal, unique `crypto.randomUUID()` IDs, Active/Inactive
     toggle, and safe delete confirmation (blocked when referenced by any active
     Studio Package).
2. Section 02 — Recording Options:
   - Existing V2 defaults: Tracking Reguler (`hourly`, Rp 150.000/jam), Live
     Recording Session (`fixed`, 3h, Rp 420.000), Multitrack Shift (`fixed`,
     6h, Rp 800.000).
   - Supports Hourly vs Fixed mode, duration locking on Fixed, Add/Edit/Toggle/Delete.
3. Section 03 — Studio Packages:
   - Existing V2 defaults: Paket Rehearsal 3 Jam (Rp 300.000 - Rp 30.000 = Rp 270.000)
     and Paket Rehearsal 5 Jam (Rp 500.000 - Rp 50.000 = Rp 450.000), default
     commissions = Rp 0.
   - Live customer price preview (`finalPrice = max(0, basePrice - discountAmount)`),
     discount <= basePrice validation, internal `staffCommissionAmount` and
     `recordingOperatorCommissionAmount`, Add/Edit/Toggle/Delete confirmation.
4. Section 04 — Discount Presets:
   - Empty by default (`discounts: []`).
   - Supports Add/Edit/Toggle/Delete for regular non-package session discounts.
   - Automatic selection chooses the single highest `discountAmount` active
     preset matching `sessionTypeId` and `durationMinutes >= minimumDurationMinutes`,
     capped at subtotal, never stacked with package or multiple discounts.
5. Section 05 — Staff and Operational Fees:
   - `rehearsalStaffCommissionPerHour` (default `0`): hourly studio guard fee
     applied only to regular (non-package) Rehearsal sessions.
   - `dailyMealAllowancePerStaff` (default `0`): operational daily preset only;
     never charged on bookings and never generates payroll/attendance/bookkeeping
     entries.
6. Centralized Save & Dirty Guard:
   - Single `Save Changes` transactional write with Zod validation, unsaved
     changes indicator, draft preservation on save failure, remote version
     conflict detection, `beforeunload` browser guard, and guarded back-navigation
     confirmation dialog.

5. FIRESTORE SCHEMA (`settings/pricing`)
============================================================

Single centralized Firestore document at `settings/pricing`:
- `schemaVersion`: `1`
- `sessionTypes`: `[{ id, name, description, hourlyRate, isActive, sortOrder }]`
- `recordingTypes`: `[{ id, name, description, priceMode, durationMinutes, price, isActive, sortOrder }]`
- `packages`: `[{ id, name, detail, sessionTypeId, durationMinutes, basePrice, discountAmount, staffCommissionAmount, recordingOperatorCommissionAmount, isActive, sortOrder }]`
- `discounts`: `[{ id, name, sessionTypeId, minimumDurationMinutes, discountAmount, isActive, sortOrder }]`
- `fees`: `{ rehearsalStaffCommissionPerHour, dailyMealAllowancePerStaff }`
- `version`: integer incremented transactionally on each save (`1`, `2`, ...)
- `updatedAt`: Firestore `serverTimestamp()`
- `updatedByUid`: `request.auth.uid`

Zero `localStorage` fallback is used as source of truth; shared realtime hook
`usePricingSettings()` uses `onSnapshot` and cleans up cleanly on unmount without
writing default documents during render.

6. FIRESTORE SECURITY RULES UPDATES (`firestore.rules`)
============================================================

- Added `match /settings/pricing`:
  - `allow get: if isActiveStaff();`
  - `allow list: if false;`
  - `allow create`: `isActiveStaff() && isValidPricingSettings(request.resource.data) && request.resource.data.version == 1;`
  - `allow update`: `isActiveStaff() && isValidPricingSettings(request.resource.data) && request.resource.data.version == resource.data.version + 1;`
  - `allow delete: if false;`
  - Enforces top-level keys allow-list, list/map types, non-negative `fees`,
    `updatedAt is timestamp`, `updatedByUid == request.auth.uid`, and denies
    access to any sibling document under `settings/`.
- Updated `match /bookings/{bookingId}`:
  - Added `'commissionSnapshot'` to `isValidBookingKeys` and validated optional
    map structure (`staffBasis`, `staffRate`, `staffAmount`,
    `recordingOperatorAmount`, `settingsVersion`) via `isValidBookingCommissionSnapshot`.
  - Locked `unitRate`, `subtotal`, `discountAmount`, `totalAmount`, and
    `commissionSnapshot` whenever `isServiceScopeUnchanged(request.resource.data, resource.data)`
    is true, while keeping full backward compatibility with Phase 5 bookings
    that omit `commissionSnapshot`.

7. CALENDAR INTEGRATION & BOOKING SNAPSHOT COMPATIBILITY
============================================================

- `AdminCalendarPage` subscribes via `usePricingSettings()` and passes live
  settings into `BookingFormDialog`, `createBooking`, and `updateOrRescheduleBooking`.
- `BookingFormDialog` dynamically renders active Session Types, Recording Options,
  and Studio Packages, applies fixed Recording Option durations dynamically,
  computes automatic non-stacking regular discounts, and displays:
  - `CUSTOMER CHARGE` (`Subtotal`, `Discount`, `TOTAL`, `Pembayaran Awal`, `Sisa Tagihan`)
  - `INTERNAL FEE ESTIMATE` (`Staff Commission`, `Recording Operator`)
- New bookings persist `commissionSnapshot` alongside existing `unitRate`,
  `subtotal`, `discountAmount`, and `totalAmount`. Internal commissions and daily
  meal allowance never alter customer totals, DP, or remaining balance.
- Historical Protection:
  - Changing Settings never mutates historical bookings.
  - Editing customer details/notes or rescheduling date/time/room on an existing
    booking preserves its original price & commission snapshot.
  - Changing service/package/duration during edit requires explicit checkbox
    confirmation (`Terapkan harga & fee preset terbaru`) before recalculating snapshots.
  - `normalizeBookingRecord` defaults missing `commissionSnapshot` to `null` and
    `BookingDetailDrawer` displays historical Phase 5 bookings safely without migration.
