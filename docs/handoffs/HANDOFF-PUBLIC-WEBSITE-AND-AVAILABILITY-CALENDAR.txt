4. PUBLIC FIRESTORE COLLECTION SCHEMA & SECURITY RULES
--------------------------------------------------------------------------------
Canonical collections (`bookings`, `bookingSlots`, `bookingEvents`, `customers`,
`customerPhoneIndex`, `invoices`, `paymentTransactions`, etc.) remain 100%
restricted to authenticated active Staff/Owner.

New collections added to `firestore.rules` and `FIRESTORE_COLLECTIONS`:

A. `publicAvailability/{bookingId}`
   - Document ID: Opaque booking document ID (e.g. `bkg_...`).
   - Exact 6-field schema enforced by `isValidPublicAvailabilityProjectionShape`:
     - `schemaVersion`: `1` (int)
     - `date`: `'YYYY-MM-DD'` (string)
     - `studioId`: `'room-a'` | `'room-b'` (string)
     - `startMinute`: `600..1350`, multiple of 30 (int)
     - `endMinute`: `630..1380`, multiple of 30, `> startMinute` (int)
     - `updatedAt`: `timestamp`
   - Zero PII: No `customerName`, `bandName`, `phone`, `customerId`, `bookingId`
     field, `notes`, `serviceId`, pricing, invoice, payment, or staff UIDs.
   - Rules:
     - `allow read: if true;`
     - `allow create, update: if isActiveStaff() && isValidPublicAvailabilityProjectionShape(request.resource.data) && isPublicAvailabilityMatchedToCanonicalBookingAfter(request.resource.data, bookingId);`
     - `allow delete: if isActiveStaff() && isPublicAvailabilityDeleteAllowedAfter(bookingId);`

B. `publicAvailabilityMetadata/status`
   - Exact 5-field schema enforced by `isValidPublicAvailabilityMetadataShape`:
     - `schemaVersion`: `1` (int)
     - `isReady`: `bool`
     - `backfilledFromDate`: `''` or `'YYYY-MM-DD'` (string)
     - `backfillCompletedAt`: `null` or `timestamp`
     - `updatedAt`: `timestamp`
   - Rules:
     - `allow get: if docId == 'status'; allow list: if false;`
     - `allow create, update: if isActiveOwner() && docId == 'status' && isValidPublicAvailabilityMetadataShape(request.resource.data);`
     - `allow delete: if false;`

6. LEGACY BACKFILL PROCEDURE & DATA READINESS BEHAVIOR
--------------------------------------------------------------------------------
Implemented in `src/features/public-availability/services/public-availability-service.js`
(`backfillPublicAvailabilityProjections`) and exposed to the Studio Owner in the
Admin Calendar header strip (`src/features/admin/calendar/pages/AdminCalendarPage.jsx`
-> button `Sinkronkan Data Lama (Backfill)`):
1. Requires authenticated active Owner (`actorRole === 'owner'`).
2. Sets `publicAvailabilityMetadata/status.isReady = false` prior to scanning.
3. Paginates through canonical `bookings` (`date >= fromDateIso`, `pageSize <= 50`).
4. Projects active bookings (`upcoming`, `in_progress`, `completed`) and removes
   any stale projections for `cancelled` / `no_show` bookings in small write
   batches (`writeBatchSize <= 8`) to respect Firestore Security Rules
   `getAfter` limits.
5. Verifies integrity of all written projections against the scanned active
   bookings before setting `publicAvailabilityMetadata/status.isReady = true`.
